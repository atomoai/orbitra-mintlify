### `complete_device_code_flow`

```python
complete_device_code_flow(settings: ClientSettings, scope: str) -> AuthenticationRecord
```


Complete a device code flow previously started by :func:`start_device_code_flow`.

Loads the persisted flow and polls the token endpoint a single pass (non-blocking) via the
``exit_condition`` knob of MSAL's ``acquire_token_by_device_flow``. On success the token is
persisted to the shared MSAL cache (by MSAL) and the ``AuthenticationRecord`` is saved, mirroring
the combined flow. The flow file is removed on success or terminal failure, and preserved while
the login is still pending.

**Raises:**
- `ClientAuthenticationError`: if no flow is in progress, the flow expired, the login is not yet
complete, or authentication failed.


### `get_azure_credential`

```python
get_azure_credential(settings: ClientSettings, scope: str, use_device_code: Optional[bool] = None) -> TokenCredential
```


Resolve and return an Azure `TokenCredential` for authenticating requests.

Resolve and return an Azure `TokenCredential` for authenticating SDK clients.

This helper centralizes the logic for obtaining Azure credentials across
different authentication modes. It automatically detects which method to use
based on environment configuration, supporting four main flows:

1. **Client Secret Authentication** - if both `ORBITRA_APP_CLIENT_ID` and
   `ORBITRA_APP_CLIENT_SECRET` environment variables are set, a
   `ClientSecretCredential` (service principal) is returned.

2. **Managed Identity Authentication** - if the environment variable
   `assigned_identity_client_id` is defined (typical for Azure Container Apps,
   VMs, or Functions), a `ManagedIdentityCredential` is returned.

3. **Device Code Authentication** - if `ORBITRA_INTERACTIVE_LOGIN_DISABLED` is set to
   "true", a `DeviceCodeCredential` is returned. This is ideal for environments
   without a web browser, such as devcontainers or SSH sessions. The user will
   be prompted to visit a URL and enter a code to authenticate.

4. **Interactive Browser Authentication** - otherwise, it falls back to
   an `InteractiveBrowserCredential` for user-based sign-in with persistent
   token caching and an optional serialized authentication record.
   The first login opens a browser; subsequent runs reuse the cached token.

**Args:**
- `settings`: 
The client settings to use for authentication.
- `scope`: 
Resource scope requested during initial authentication.
- `use_device_code`: 
If True, force device code flow. If False, force interactive browser.
If None (default), falls back to ``settings.orbitra_interactive_login_disabled``.

**Returns:**
- 
A valid Azure credential object usable with SDK clients such as
`BlobServiceClient`, `SecretClient`, or `ResourceManagementClient`.

**Raises:**
- `ClientAuthenticationError`: 
If credentials are misconfigured or invalid.
- `CredentialUnavailableError`: 
If no suitable authentication method is available in the current environment.

### `start_device_code_flow`

```python
start_device_code_flow(settings: ClientSettings, scope: str) -> dict
```


Initiate the device code flow without blocking.

Obtains a ``user_code`` + ``verification_uri`` from Entra ID, persists the flow to
``~/.orbitra/device_flow_{tenant_id}_{client_id}.json`` and returns it immediately. The caller
is expected to display the URL + code and later call :func:`complete_device_code_flow`.

``azure.identity.DeviceCodeCredential.authenticate`` cannot be split into initiate/poll, so we
drop to MSAL's ``initiate_device_flow`` directly (see :func:`_build_device_code_app`).
