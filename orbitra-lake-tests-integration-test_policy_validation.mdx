# `orbitra.lake.tests.integration.test_policy_validation`


Behavior validation of row filters and column masks on the dev Unity Catalog (ORBITRA-1016).

Same setup as ``test_policy_apply.py`` (manager = default identity, writer and reader service
principals). Each class names its tables with its prefix in the run, ``it_<run id>_<class>_``
(the ``table_name`` fixture), and drops them at the end. Each check writes its counts to the file
in ``ORBITRA_VALIDATE_REPORT`` (JSON lines) when it is set.

1. Concurrent updates: 4 processes, 3 rounds; every call ends in success or the lock error, and the
   table ends readable and equal to one declaration of the round.
2. The lock: an old lock blocks with an actionable error; the lock goes after a success and after a
   failure; drop and create again with the same name.
3. Reads during updates: the reader never sees a masked value in clear nor a row outside its rules.
4. The writer: equal declaration writes nothing and takes no lock; a different one fails on the lock POST
   (the manager check) and changes nothing.
5. Edge cases: mixed case, quotes and backslashes, a partition column, 20 principals.
