# `orbitra.lake.tests.utils`

## Functions

### `df_to_snapshot_json`

```python
df_to_snapshot_json(df: pd.DataFrame) -> str
```


Serialize a DataFrame exactly like pandas 2's default ``to_json`` so the snapshot files stay valid on pandas 3.

pandas 2 emitted a datetime64 column as its int64 values // 10**6 regardless of resolution
(whole seconds for the microsecond timestamps Iceberg returns), ``datetime.date`` objects as epoch
milliseconds and ``Decimal`` objects as numbers. pandas 3 emits milliseconds for every resolution,
Decimals as strings and deprecates the 'epoch' date format. The conversions are done here explicitly
so the output is independent of the pandas major version and the snapshots did not have to change.


### `run_competing_writer_before_data_commit`

```python
run_competing_writer_before_data_commit(monkeypatch, competing_write: Callable[[], object]) -> dict[str, bool]
```


Run ``competing_write`` once, just before the next commit that adds rows reaches the catalog.

The returned flag turns ``done`` once the competitor ran. The competitor's own commits pass through untouched.


### `setup_method`

```python
setup_method(request, tmp_path_factory)
```


Fixture to set up the mock client for testing.

This fixture initializes the Orbitra Lake client with the specified database mode and cleans up after tests.
The local catalog and the local raw storage live in a temporary directory of their own per test class, so the
classes can run in parallel (pytest-xdist) without sharing a SQLite catalog.
