# `orbitra.lake.tests.integration.test_policy_apply`


Apply row filters and column masks on the dev Unity Catalog (ORBITRA-1016), with the golden check of ORBITRA-1015.

Needs the lake module of ORBITRA-1014 in the tenant (governed tags, assigner rule set, READ_METADATA).
The tests run in the namespace of the integration suite, ``e2e_tests`` (``NAMESPACE`` in ``conftest.py``).
The default identity (az CLI or ``ORBITRA_APP_CLIENT_ID``) must be in its manager group. Two service
principals of the namespace are also needed, one in the writer group and one in the reader group (the
subject of the policies): ``ORBITRA_TEST_TENANT_ID``, ``ORBITRA_TEST_WRITER_CLIENT_ID``/``_SECRET`` and
``ORBITRA_TEST_READER_CLIENT_ID``/``_SECRET``. Each class names its tables with its prefix in the run,
``it_<run id>_<class>_`` (``run_registry.py``), and drops them at the end; when a run dies, the next run
drops its tables with their lock and filter UDFs (``run_registry.clean_dead_runs``).
Shared mask UDFs (``__orbitra_mask_*``) are never deleted by the SDK.



Name a table of the test's class: ``kind`` -> ``it_<run id>_<class>_<kind>``, as in the other integration tests.

Two runs, or two classes of one run, then never share a table, nor its lock and filter UDFs, whose names
derive from the table name.

Test that GOLDEN has every action on every SDK type the action allows (no Databricks call).
