# `orbitra.lake.tests.integration.isolation`


Isolate one integration test class by a prefix on every table and saved query it creates.

The shared test classes (orbitra/lake/tests/lake) use fixed names such as ``inf_diario_fi`` and ``test_data``.
``isolate_client`` patches one client so that the SDK and the tests still see those plain names, while Unity Catalog
and the raw storage hold ``<prefix><name>``. Two runs, or two classes of one run, then never touch the same objects.

The patch is on the client instance only, at these points:

- ``db.catalog``: a proxy that adds the prefix to every table identifier and lists only the prefixed tables. The
  ``_get_catalog`` of the instance returns the proxy too, so ``refresh_token`` keeps it.
- ``db._run_query_local_engine`` and ``db._get_duckdb_connection``: DuckDB resolves plain names through views
  ``memory.main.<name>`` on ``iceberg_catalog.<namespace>.<prefix><name>``.
- ``db._run_query_remote_engine``: the plain names of the prefixed tables are replaced in the SQL text.
- ``db.full_table_name``: the Unity Catalog REST calls of the access policies (``drop_table`` takes the lock of
  the table and reads its row filter) use ``<prefix><name>``, so the lock and filter UDF names, which derive from
  it, are of the prefixed table too.
- ``saved_query_service.raw_service``: saved queries live under ``<root>/.orbitra/saved_queries`` instead of
  ``.orbitra/saved_queries`` in the raw container.


## Functions

### `isolate_client`

```python
isolate_client(client: OrbitraLakeClient, prefix: str, saved_query_root: str) -> None
```


Patch ``client`` so that its tables are ``<prefix><name>`` and its saved queries live under ``saved_query_root``.


## Classes

### `PrefixedCatalog`


Catalog proxy: the caller uses plain table names, the wrapped catalog gets ``<prefix><name>``.

It fails closed. The methods in ISOLATED add the prefix, the methods in PASS_THROUGH take no table identifier and
go to the wrapped catalog unchanged, and any other attribute raises. A new catalog call in the SDK then fails the
integration tests instead of reaching a table without the prefix; tests/test_integration_isolation.py also checks the SDK source.
